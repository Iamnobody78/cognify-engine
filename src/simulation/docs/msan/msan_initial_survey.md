## 1. MSAN-ENGINE v1.0 元提示词（装载）

MSAN-ENGINE v1.0 定义多传感器自主导航的元提示协议，作为 BottleSumo 治理智能体
跨域扩展的监督框架。核心四传感器轴：

```
┌─────────────────────────────────────────────────────────┐
│  MSAN-ENGINE v1.0 — 多传感器自主导航元提示               │
├─────────────────────────────────────────────────────────┤
│  S1 雷达 (Radar):    4D 成像雷达 / 毫米波, 恶劣天气鲁棒    │
│  S2 导航 (Navigation): 位姿估计 / 路径规划 / SLAM          │
│  S3 RTK (GNSS-RTK):  厘米级绝对定位, 基线校正              │
│  S4 IMU (惯性):      高频姿态/加速度, 航迹推算 (DR)        │
│                                                        │
│  融合原则: 松耦合优先 → 紧耦合 (LVI-SLAM 风格)             │
│  验证原则: 仿真数据集优先 → 实物 (BottleSumo 底盘)         │
│  交付原则: 与现有 14 层工具链共用治理/门禁协议              │
└─────────────────────────────────────────────────────────┘
```

**装载范围 (建议 v0.1 试点)**: 雷达 (S1) + RTK (S3) 双轴 — 与 BottleSumo 机器人
底盘最直接相关（避障 + 厘米级定位），IMU/导航为后续。

## 5. 优先级排序（建议装载顺序）

```
阶段 0 (调研完成 — 本次): 资源扫描 + 元提示装载                ← 当前
阶段 1 (P0, 数据):        NTU4DRadLM + M2DGR 下载/格式解析
                           → 建立统一数据管道 (治理层登记)
阶段 2 (P0, 标定):        GICI-LIB 装载 → 雷达-LiDAR-IMU 时空标定
                           → 仿真 (Gazebo) 内验证标定质量
阶段 3 (P1, 融合):        松耦合 4D 雷达 + RTK 定位原型
                           → 门禁: 仿真定位精度 vs 地面真值
阶段 4 (P2, 部署):        实机 BottleSumo 底盘试点 (仅当门禁通过)
```

**门槛 (建议)**: 每阶段沿用 V9 裁决门精神 — 阶段 2 门禁 = 标定残差 < 阈值;
阶段 3 门禁 = RTK-融合位姿 RMSE 对比纯 RTK 不劣化。未过门禁不进入下一阶段。
