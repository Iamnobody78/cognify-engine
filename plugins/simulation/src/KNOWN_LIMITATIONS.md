# 已知限制（Known Limitations）

> 本文档如实记录当前版本的已知限制。**不粉饰、不拖延**——每项均有对应处置路径。
> 更新时间: 2026-08-11

## 安全与验证

| # | 限制 | 影响 | 处置 |
|---|------|------|------|
| 1 | **验证器为语法/规则级基线**（`BaselineDeclarationValidator` + `JSONSchemaVerifier`），LLM 语义验证与签名验证为路线图项 | 无法检测语义级谎报（如"代码能编译"但逻辑错误） | CORE-01 已落地 JSON Schema 校验；签名验证排期 |
| 2 | **fail-open 策略**（审计回调失败不阻塞裁决） | 当审计系统自身故障时，恶意请求可能绕过审计记录 | 设计为"审计可用性优先"；生产部署建议切换 fail-closed（配置 `FAIL_POLICY=closed`） |
| 3 | **JWT 无 refresh 机制**（TTL 默认 12h，`GOV_AUTH_TTL_HOURS` 可配置） | 令牌过期后需重新登录 | 有意的 v1 简化；refresh token 排期 |
| 4 | 密码策略为最小校验（非空 + 长度 ≥ 8） | 无复杂度强制 | 排期：强度策略 + 旧密码禁止复用 |

## 资产与仿真

| # | 限制 | 影响 | 处置 |
|---|------|------|------|
| 5 | **140GB 仿真资产不在 git 范围内**（见 [资产策略](#资产策略)） | 全新环境无法立即复现完整仿真 | 资产清单 + 外部存储下载计划（P1） |
| 6 | CI 仅覆盖单元 + E2E 冒烟，未跑 140GB 仿真 | 仿真层回归风险 | 资产落地外部存储后接 CI 冒烟（路线图） |
