## 1. 页面清单与五问批判

### N1. 人機協作協議 · 元模型控制工程提煉
- **内容是什么**: 11 列协议表（协议模組/分類/層級/核心目的/元認知提問/人機協作指令/觸發情境/自我檢核·倫理邊界/來源對應/操作頻率/實作策略/預期產出）→ 从思考习惯到操作系统的部署蓝图
- **核心价值**: 协议表的 11 列结构 = 完整的行为规范 schema——可直接编译为 YAML/JSON 协议规范，且每列都对应可执行字段（触发条件→条件分支，操作频率→调度，伦理边界→安全检查）
- **假设/局限**: 假设协议是静态的（一次定义终生使用）；但"除错循环"暗示需要迭代——元层反馈缺失
- **对 BottleSumo 治理的可迁移性**: **高**——协议表 schema 可作为治理规则的声明式规范；`自我檢核/倫理邊界` 列与我们的红线机制同构
- **迁移成本**: 低（schema 编译），但需决定"协议库"存放位置（governance/protocols/）

### N2. 元模型控制工程 (MMCE) 核心框架
- **内容是什么**: 四能力（模型识别/模型外化/模型并行/模型切换权争夺）+ L1-L6 层级
- **核心价值**: 四能力本质是**元认知操作原语**——可编译为 `mmce_toolkit.py`（每能力一个函数）+ 话术模板库（utterance templates）
- **假设/局限**: 面向人类对话场景；应用到 AI 治理时需映射"对方模型"为"对方 agent 的策略模式"——语义迁移需谨慎
- **对 BottleSumo 治理的可迁移性**: **中高**——"模型识别"可映射为 agent 行为模式分类（如检测另一个 agent 是否在用防御性策略）；L1-L6 可作为元治理的成熟度阶梯
- **迁移成本**: 中（需要把对话话术映射为 agent 行为检测）

### N3. Aionui 记忆库设计 (.aionui/ 目录方案)
- **内容是什么**: tools/config/context/sessions/templates 五目录 + README/manifest.json 模板 + 会话恢复机制
- **核心价值**: **高**——这是可立即执行的目录方案；与我们的 `.aionui/` 元提示词体系直接兼容（meta_prompts/loaded/ 已在用）
- **假设/局限**: 假设目录是静态结构；实际使用中文件会快速增长（sessions/ N+1）——需要清理策略
- **对 BottleSumo 治理的可迁移性**: **高**——可直接落地为 `governance/memory/` 脚手架；会话恢复机制解决"新对话上下文丢失"痛点
- **迁移成本**: 低（纯文件生成）
