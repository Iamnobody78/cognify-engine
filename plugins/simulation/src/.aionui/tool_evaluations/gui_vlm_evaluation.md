## 核心判断
1. **语义鸿沟**：ShowUI/UI-TARS 等训练于**网页/桌面 GUI 截图**（按钮、表单、菜单），
   而我们的 GUI 是 **RViz 3D 俯视场景**（圆柱体、土俵环、轨迹线）——VLM 理解能力存疑。
2. **替代方案更优**：`/bottlesumo/vis/state` 数值桥接已提供**完整、精确、无噪声**的状态
   （坐标、朝向、奖励、决策模式）。VLM 从截图恢复这些信息是"有损压缩回放"，ROI 低。
3. **内存硬约束**：5.8G 内存下仅 0.5B/256M 级可行，此类模型对 3D 场景的视觉理解本就薄弱。

## 最终建议
**暂缓部署**。当前阶段"眼睛"= 数值桥接（已实现）。
VLM 仅在未来"人类可读演示/教学"或"多模态验收"场景下引入，届时优先 ShowUI 0.5B 量化版；
先决条件是安装 Ollama（系统提示声称存在但实测未装，记忆需校正）。
